AI 찍기에 "실험용 조절 기능"을 추가해 줘. 이번 작업 목표는
"모델·파라미터·출력 형식·시스템 프롬프트를 바꿔 가며 결과를 비교할 수 있게 하기" 하나뿐이야.
명령(이동·색 교체) 방식 수정, 여러 칸 자동 생성, Batch API는 아직 넣지 마.

배경: openai/gpt-4o-mini로 시험했더니 48줄 대신 45줄, 45줄 중 36줄이 47글자, 5색 팔레트 중 1색만 써서
형식도 그림도 실패했어. 이제 최상위 모델(openai/gpt-6.1-sol 등)로 비교하려고 해.
양이 많으니 맨 아래 "작업 순서"대로 하나씩 끝내면서 진행해.

## 0. 원칙
- 고칠 파일: js/ai.js, index.html, 필요하면 css/style.css.
  예외로 js/main.js는 keydown 핸들러의 대화상자 검사 한 줄만 고쳐도 됨 (9번 참고). 다른 파일은 건드리지 마.
- 전체 파일을 새로 쓰지 말고 필요한 부분만 고쳐.
- git 커밋은 하지 마. 검토 후 따로 함.
- 기존 동작(응답 붙여넣기, 프롬프트 복사, 오류 안내, 키 확인)은 그대로 유지.
- 기존 스타일(CSS 변수, .btn, 다크모드, [hidden] 규칙, dialog 모양)을 따를 것. 외부 라이브러리 추가 금지.
- 이전 작업 지시는 tasks/ 폴더에 있어. 참고만 해.

## 1. 모델 정보 불러오기
- GET https://openrouter.ai/api/v1/models (키 필요 없음). 앱 시작 후 AI 설정을 처음 열 때 한 번만 불러와서 메모리에 보관.
- 모델 이름 입력칸 아래에 선택한 모델 정보를 한 줄로 표시:
  입력/출력 가격($/100만 토큰), 지원 파라미터 중 아래 2번에 나오는 것들의 지원 여부.
  - 가격은 응답의 pricing.prompt, pricing.completion(토큰당 달러 문자열) × 1,000,000.
  - 지원 여부는 응답의 supported_parameters 배열.
- 모델 이름 입력칸에 <datalist>로 목록의 모델 id를 자동완성으로 붙여 줘.
- 모델 이름이 목록에 없으면 "OpenRouter에 없는 모델 이름이에요" 경고 (호출은 막지 않음).
  단 8번의 test/ 가짜 모델은 경고하지 않음.
- 이름 끝이 :batch인 모델을 넣으면 "batch 모델은 결과가 늦게(수 분~24시간) 와서 찍기에 쓸 수 없어요" 경고.
- 불러오기 실패해도 다른 기능은 정상 동작. 실패하면 정보 줄에 "모델 정보를 불러오지 못했어요"와 [다시 불러오기] 버튼.

## 2. 요청 파라미터 (AI 설정 창에 "고급" 영역)
| 항목 | 보내는 값 | 기본값 |
|---|---|---|
| 추론 강도 | reasoning: { effort: "low" / "medium" / "high" } | 보내지 않음(모델 기본) |
| 최대 출력 토큰 | max_tokens | 보내지 않음 |
| temperature | temperature (0~2) | 보내지 않음 |
| seed | seed (정수) | 보내지 않음 |
- 비어 있는 항목은 요청 body에 아예 넣지 마. 범위 밖이거나 숫자가 아니면 입력칸 옆에 경고, 보내지 않음.
- 1번 모델 정보에서 지원하지 않는 항목은 입력칸을 비활성화하고 "이 모델은 지원 안 함" 표시.
  비활성화된 항목은 값이 있어도 보내지 않음 (값은 지우지 말고 남겨 둠).
  (예: openai/gpt-6.1-sol은 temperature 미지원. 모델 정보를 못 불러왔으면 비활성화하지 않음)
- 모든 요청 body에 usage: { include: true } 추가 → 응답 usage에 cost(달러)가 오면 디버그와 기록에 표시.
  - cost가 없으면 1번 가격 × 토큰 수로 계산해서 "(추정)"을 붙여 표시. 가격도 모르면 "알 수 없음".
- 응답 usage에 reasoning_tokens(또는 completion_tokens_details.reasoning_tokens)가 있으면 같이 표시.
- 응답의 choices[0].finish_reason과 응답의 model(실제로 처리한 모델 id)도 디버그와 기록에 표시.
  - finish_reason이 "length"이면 형식 오류보다 먼저 이 안내를 띄움:
    "출력 토큰이 모자라서 응답이 잘렸어요 (최대 출력 토큰을 늘리거나 추론 강도를 낮춰 보세요)".
    추론 모델은 추론에 토큰을 다 써서 content가 비어 오는 경우가 있어. 이때도 "빈 응답" 대신 이 안내.
- 설정값은 'dot-gongbang.ai' localStorage에 함께 저장 (키 저장 방식은 그대로).

### callAI 구조
- callAI(messages, signal, opts) → { text, usage, finishReason, model }
  - opts = { model, params } (params = 2번 표의 값 중 실제로 보낼 것만). OpenRouter body 조립은 callAI 안에서만.
  - 화면 코드는 지금처럼 OpenRouter 세부 사항을 몰라야 해.
- 찍기 버튼을 누른 순간의 설정(모델, 파라미터, 형식, 시스템 프롬프트, 자동 보정)을 하나의 객체로 복사해서
  그 호출이 끝날 때까지 그 값만 씀. 호출 중에 설정을 바꿔도 진행 중인 호출과 기록에는 영향 없음.
- 디버그에 "보낸 요청 body"를 표시. messages는 "(messages 2개, 12345자)"처럼 요약하고 나머지 필드는 JSON 그대로.
  (완료 기준 1번을 이걸로 확인함. 키는 헤더에만 있으니 body에는 없어야 함)

## 3. 출력 형식 선택 (3가지)
AI 패널에 [출력 형식] 선택: 격자 / 줄번호 격자(기본) / 줄 압축(RLE)
- 격자: 지금 형식 그대로.
- 줄번호 격자: 각 줄 앞에 두 자리 줄 번호와 "| "를 붙여 출력하게 함. 예) "07| 000011112222..."
  - 줄 접두어는 관대하게: /^\s*(\d{1,3})\s*\|\s?/ (번호 앞뒤 공백, | 뒤 공백 0~1개).
  - 파서는 줄 번호로 줄 위치를 정함. 같은 번호가 두 번 나오면 실패. 번호가 0~N-1 밖이면 실패.
  - 번호가 없는 줄이 GRID 안에 있으면 실패 (몇 번째 줄인지 표시).
  - 빠진 줄 번호가 있으면 실패하고 빠진 번호를 표시 (단 4번 자동 보정이 켜져 있으면 빈 줄로 채움).
- 줄 압축(RLE): 각 줄을 "기호*개수"를 공백으로 이어서 출력. 예) "07| 0*16 1*4 2*8 0*20"
  - 토큰 형식은 /^([0-9a-z])\*(\d+)$/i, 개수는 1 이상. 형식이 틀린 토큰이 있으면 그 토큰과 줄 번호를 표시하고 실패.
  - 줄마다 개수 합이 정확히 N이어야 함. 합이 틀리면 몇 번째 줄이 합 몇인지 표시하고 실패.
  - 줄 번호 규칙은 줄번호 격자와 같음.
- 형식마다 시스템 프롬프트의 출력 형식 설명과 예시가 바뀌어야 함 (5번 템플릿 참고).
  예시는 실제 N 크기로 만들지 말고 짧은 예 한두 줄 + "each line exactly {N} characters / counts sum to {N}" 설명.
- 입력으로 보내는 그림(대상·참고)은 지금처럼 줄 번호·눈금이 붙은 격자 그대로.
- [응답 직접 붙여넣기]도 지금 선택된 출력 형식과 자동 보정 설정으로 파싱. 붙여넣기 대화상자에 "형식: 줄번호 격자" 표시.
- 실패 이유는 처음 하나만 말고 최대 5개까지 모아서 보여 줘 (예: "3번째 줄 47글자, 9번째 줄 47글자, ... 외 31개").
  실험할 때 어떤 식으로 틀리는지 봐야 해서야.

## 4. 자동 보정 (체크박스, 기본 꺼짐)
- 격자 / 줄번호 격자:
  - 줄 글자 수가 N보다 1~2 모자라면 오른쪽을 0(투명)으로 채움.
  - 줄 글자 수가 N보다 1~2 많고, 넘치는 글자가 전부 0이면 잘라냄. 0이 아닌 글자가 넘치면 실패.
  - 줄번호 격자에서 빠진 줄이 2개 이하면 빈 줄로 채움.
- 줄 압축(RLE):
  - 합이 N보다 1~2 모자라면 오른쪽을 0으로 채움.
  - 합이 N보다 1~2 많고, 넘치는 부분이 전부 0이면 잘라냄. 0이 아닌 칸이 넘치면 실패.
  - 빠진 줄 규칙은 줄번호 격자와 같음.
- 보정이 일어나면 적용은 하되 토스트와 디버그에 "보정: 줄 N개 채움, 줄 N개 자름, 빠진 줄 N개" 표시.
- 보정 범위를 넘으면 지금처럼 실패.

## 5. 시스템 프롬프트 편집
- AI 설정 "고급" 영역에 시스템 프롬프트 textarea + [기본값으로] 버튼.
- 템플릿 안의 {N}은 캔버스 크기, {FORMAT}은 3번에서 고른 형식의 설명·예시로 바꿔서 보냄.
- 기본 템플릿은 지금 시스템 프롬프트를 바탕으로, 출력 형식 부분만 {FORMAT}으로 뺀 것.
- 저장은 'dot-gongbang.ai'. 비어 있으면 기본값 사용.
- 템플릿에 {FORMAT}이 없으면 경고 표시 (보내는 건 막지 않음).
- 기본값과 다르면 textarea 위에 "수정됨" 표시.

## 6. 후보 여러 장
- AI 패널에 [후보 수] 1~4 (기본 1). 'dot-gongbang.ai'에 저장.
- 2 이상이면 같은 메시지로 동시에 그 수만큼 호출 (seed가 설정돼 있으면 seed, seed+1, ...).
- [취소]는 진행 중인 후보 전부를 중단. 이미 끝난 후보 결과는 그대로 대화상자에 표시.
- 결과를 대화상자에 썸네일로 나란히 표시 (픽셀이 보이게 image-rendering: pixelated, 투명은 체크무늬).
  - 후보마다: 성공/실패, 실패 이유, 보정 내용, 출력 토큰, 비용, 걸린 시간.
  - 성공한 후보를 누르면 대상 칸에 적용 (되돌리기 한 번으로 복구). 아무것도 안 고르고 닫으면 그림 그대로.
  - 결과는 호출을 시작할 때의 대상 칸에 적용 (지금 단일 호출과 같은 규칙).
- 마지막 후보 묶음은 메모리에 보관하고 AI 패널에 [후보 다시 보기] 버튼 (후보가 있을 때만 보임).
  다시 보기에서 다른 후보를 고르면 그것도 되돌리기 한 번 단위로 적용.
- 후보 수 × 예상 비용이 커질 수 있으니, [찍기] 버튼 옆에 "후보 N장" 표시.
- 1이면 지금처럼 바로 적용.

## 7. 실험 기록
- 호출(후보 각각)마다 한 줄씩 기록, 'dot-gongbang.ailog' localStorage에 최근 200개 보관:
  시각, 모델(보낸 이름), 실제 모델(응답의 model), 출력 형식, 추론 강도/max_tokens/temperature/seed,
  시스템 프롬프트 기본/수정 여부, 대상 칸 이름, 생성/수정, 후보 번호(예: 2/3), 사용자 프롬프트 앞 60자,
  성공/실패/취소, 실패 이유, 보정 내용, finish_reason, 입력/출력/추론 토큰, 비용(추정이면 표시), 걸린 시간(ms).
- 응답 원문은 기록에 넣지 말고 'dot-gongbang.airaw'에 최근 20개만 따로 보관 (기록 id로 연결).
  표에서 원문이 남아 있는 줄은 [원문] 버튼으로 볼 수 있게.
- API 키는 절대 기록하지 마.
- localStorage 저장이 실패(용량 초과)하면 오래된 것부터 지우고 다시 시도. 그래도 실패하면 조용히 넘어감.
- AI 패널의 디버그 아래에 [기록 보기] → 대화상자에 표로 표시 (최근순), [CSV로 저장] (기존 saveFile 사용),
  [기록 지우기] (확인 후).
  - 표는 대화상자 안에서만 가로 스크롤 (페이지 전체가 가로로 밀리면 안 됨).
  - CSV는 UTF-8 BOM을 붙여서 엑셀에서 한글이 깨지지 않게. 쉼표·따옴표·줄바꿈은 CSV 규칙대로 감싸기.
  - 표 위에 간단 요약 한 줄: 모델+형식별 "성공 N / 전체 M, 평균 비용, 평균 시간".

## 8. 테스트용 가짜 모델 (비용 없이 완료 기준 확인용)
- 모델 이름이 "test/"로 시작하면 네트워크 호출 없이 가짜 응답을 돌려줌. 키가 비어 있어도 동작.
- 이 경로도 callAI 안에서 처리 (화면 코드는 진짜/가짜를 구분하지 않음). 요청 body는 진짜와 똑같이 만들어서 디버그에 표시.
- 모델 이름이 test/일 때만 "고급" 영역에 [가짜 응답] textarea가 보임 ('dot-gongbang.ai'에 저장).
  - "=====" 한 줄로 여러 응답을 나눔. 후보 i번은 i번째 응답을 씀 (모자라면 마지막 것을 반복).
  - 특수 응답:
    - "!http 401 {본문}" → 그 상태 코드와 본문으로 HTTP 오류를 던짐 (3단계 오류 안내 확인용).
    - "!empty length" → content 빈 문자열, finish_reason "length".
  - 일반 응답은 finish_reason "stop", model은 입력한 이름 그대로.
- 가짜 usage: prompt_tokens = 보낸 글자 수/4 반올림, completion_tokens = 응답 글자 수/4 반올림,
  completion_tokens_details.reasoning_tokens = 0, cost = 0.000001 × (두 토큰 합).
- 응답 전에 500ms 기다림 (signal로 취소 가능해야 함). 찍는 중 표시와 [취소]를 확인하기 위해서야.

## 9. 기존 코드 손질 (이번에 같이)
- setAiDebug가 성공할 때도 디버그 <details>를 항상 여는 것: 실패할 때만 자동으로 열기.
- aiFormatError가 지금 입력칸의 모델 이름을 씀: 호출할 때의 모델 이름을 쓰도록 (2번 "설정 복사" 객체 사용).
- user 메시지 안의 "참고:", "대상 그림:" 라벨을 영어로 ("Reference: down standing (pattern 1)", "Target picture:").
  화면 표시(aiTargetLine 등)는 한국어 그대로.
- js/main.js keydown의 대화상자 검사: 대화상자를 하나씩 나열하지 말고 document.querySelector('dialog[open]')로 바꿔서
  새 대화상자(후보, 기록)가 열려 있을 때도 단축키가 동작하지 않게. (main.js는 이 한 줄만)

## 10. 완료 확인 기준 (8번 가짜 모델로 비용 없이 확인 가능해야 함)
1. 비어 있는 파라미터는 디버그의 "보낸 요청 body"에 없고, 채운 파라미터만 들어감. usage: { include: true }는 항상 들어감.
   body 어디에도 API 키가 없음.
2. 모델 정보에서 temperature 미지원인 모델(예: openai/gpt-6.1-sol)을 고르면 temperature 입력칸이 비활성화되고,
   값이 남아 있어도 body에 temperature가 없음.
3. 세 가지 출력 형식 각각: 올바른 응답은 적용, 줄 수·글자 수(또는 RLE 합)가 틀린 응답은 이유와 함께 거부.
   실패 이유가 여러 개면 최대 5개까지 표시.
4. 줄번호 격자·RLE에서 줄 순서가 섞여 있어도 줄 번호대로 정확히 배치됨. 같은 번호 두 번이면 거부.
5. 자동 보정 켬: 47글자 줄이 있는 응답은 오른쪽이 투명으로 채워져 적용되고 보정 내용이 표시됨.
   자동 보정 끔: 같은 응답이 거부됨. RLE 합 47인 줄도 같은 방식.
6. 후보 3장(가짜 응답 3개 중 1개는 틀린 형식): 대화상자에 성공 2, 실패 1이 각각 표시되고, 고른 것만 적용되며,
   되돌리기 한 번으로 원래 그림. 다른 11칸은 픽셀 단위로 변하지 않음. 기록에 3줄이 추가됨.
7. 후보 3장 진행 중 [취소] → 세 호출 모두 중단, 그림 그대로, 기록에 "취소".
8. "!empty length" 가짜 응답 → "출력 토큰이 모자라서…" 안내가 뜨고 기록 finish_reason에 length.
9. "!http 401 {"error":{"message":"User not found.","code":401}}" → 3단계와 같은 한국어 안내와 디버그 기록.
10. 응답 usage에 cost가 있으면 디버그와 기록에 표시. 기록 CSV에 API 키가 없고, 엑셀에서 한글이 깨지지 않음.
11. 시스템 프롬프트를 고치면 [보낼 프롬프트 복사] 결과에 반영되고, [기본값으로]로 되돌아감.
    출력 형식을 바꾸면 복사 결과의 형식 설명이 바뀜.
12. 새로고침 후에도 파라미터, 형식, 후보 수, 시스템 프롬프트, 자동 보정, 기록이 유지됨.
13. 기존 기능(응답 붙여넣기, 오류 안내, 키 확인, 실제 OpenRouter 호출, MZ 내보내기/불러오기, JSON 저장/불러오기, 되돌리기)
    모두 그대로 동작. 프로젝트 JSON에 AI 설정·기록이 들어가지 않음.
14. 다크모드/모바일(360px)에서 새 UI(고급 영역, 후보 대화상자, 기록 표)가 깨지지 않고 페이지 가로 스크롤이 생기지 않음.
15. index.html을 더블클릭(file://)으로 열었을 때 콘솔 오류 0개.
