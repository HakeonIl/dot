## 1. API 키 앞뒤 공백 제거 (원인 후보 1순위)
- 지금 js/ai.js의 #aiKey input 핸들러는 키를 trim하지 않아 (모델 이름은 trim함).
- 키를 복사할 때 앞에 공백이 붙으면 헤더가 "Bearer  sk-..."(공백 2칸)가 되어
  OpenRouter가 401 "Missing Authentication header"를 돌려줘. 실제로 확인한 동작이야.
- 수정: 입력 핸들러, localStorage에서 불러올 때, callAI 안에서 쓸 때 모두 .trim() 적용.
  키 중간에 공백이나 줄바꿈이 있으면 저장은 하되 설정 창에 "키에 공백이 들어 있어요" 경고 표시.

## 2. 오류를 디버그 영역에 남기기
- doAiGenerate의 catch에서 토스트만 띄우지 말고 setAiDebug로 디버그 영역에도 기록:
  - 시각, 모델 이름, HTTP 상태 코드, 응답 본문 전체(최대 2000자, 지금은 200자에서 잘림)
  - 키는 절대 기록하지 마. 필요하면 앞 8자 + "…" + 길이만 (예: "sk-or-v1… (73자)")
- 오류가 나면 디버그 <details>를 자동으로 열기.
- callAI는 오류를 던질 때 status와 본문을 담아서 던져 (예: err.status, err.body). 화면 코드가 그걸 씀.

## 3. 자주 나는 오류는 한국어 안내 추가
OpenRouter 응답 본문의 error.message를 보고 토스트·디버그에 안내를 붙여:
| 상태 | 메시지 | 안내 |
|---|---|---|
| 401 | Missing Authentication header | 키 앞에 공백이 있거나 키 형식이 이상해요 |
| 401 | User not found. | OpenRouter 키가 아니거나, 삭제됐거나, 일부만 복사됐어요 (sk-or-v1-로 시작해야 함) |
| 401 | No cookie auth credentials found | 키가 전송되지 않았어요 |
| 402 | (아무거나) | OpenRouter 크레딧이 부족해요 |
| 429 | (아무거나) | 요청이 너무 많아요. 잠시 후 다시 시도 |
| 400 | 본문에 model 관련 내용 | 모델 이름을 확인해 주세요 (OpenRouter 모델 페이지의 ID를 그대로) |
- 표에 없는 오류는 상태 코드와 error.message를 그대로 보여 줘.
- 토스트는 오류일 때 6초 정도로 길게 (다른 토스트 시간은 그대로).

## 4. AI 설정 창에 [키 확인] 버튼
- GET https://openrouter.ai/api/v1/key, 헤더 Authorization: Bearer <키>. 비용이 들지 않는 요청이야.
- 200이면 "키 정상" + 응답 data의 label, limit, usage 정도를 짧게 표시.
- 실패면 3번 표의 안내를 그대로 표시.

## 5. 완료 확인 기준
1. 키 앞뒤에 공백을 넣고 붙여넣어도 공백이 제거되어 저장되고, 요청 헤더가 "Bearer sk-..."(공백 1칸)임.
2. 가짜 키(sk-or-v1-fake)로 [찍기]를 누르면 디버그 영역이 열리고
   상태 401, 응답 본문 {"error":{"message":"User not found.","code":401}}, 한국어 안내가 보임.
3. 가짜 키로 [키 확인]을 누르면 같은 안내가 보임.
4. 디버그 영역, 토스트, 콘솔 어디에도 API 키 전체가 찍히지 않음.
5. 기존 AI 기능(응답 붙여넣기, 프롬프트 복사, 정상 호출)과 다른 모든 기능이 이전과 똑같이 동작.
