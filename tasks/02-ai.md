dot.html에 "AI로 찍기" 기능을 추가해 줘. 이번 작업 목표는
"OpenRouter로 AI를 불러서, 지금 선택한 칸 한 장을 새로 그리거나 고치기" 하나뿐이야.
여러 칸 자동 생성, 명령(이동·색 교체 등) 방식 수정, AI가 이미지를 보고 고치기는 아직 넣지 마.

## 0. 원칙
- 기존 코드 구조와 디자인(CSS 변수, 버튼 스타일, 다크모드, [hidden] 규칙)을 유지하고 필요한 부분만 추가해.
- 자유 모드 / MZ 캐릭터 모드의 기존 기능은 지금처럼 그대로 동작해야 해.
- 결과는 수정된 전체 HTML 파일 하나로 줘.

## 1. AI 설정
- "AI 설정" 영역 추가 (저장·내보내기 대화상자 안이든 별도 대화상자든 기존 스타일에 맞게).
  - OpenRouter API 키 입력칸 (type=password, 보이기/숨기기 토글)
  - 모델 이름 입력칸 (자유 입력, 예: anthropic/claude-..., openai/gpt-...). 기본값은 비워 둠.
- 키와 모델 이름은 별도 localStorage 키(예: 'dot-gongbang.ai')에만 저장.
  - 프로젝트 JSON 저장, 프로젝트 localStorage(v2), undo 스냅샷에는 절대 들어가면 안 됨.
- 키나 모델이 비어 있는데 찍기를 누르면 "AI 설정에서 키와 모델을 입력해 주세요" 토스트 + 설정 열기.

## 2. AI 호출
- 호출은 함수 하나로 분리: async callAI(messages, signal) → { text, usage }
  - POST https://openrouter.ai/api/v1/chat/completions (OpenAI 호환 형식)
  - 헤더: Authorization: Bearer <키>, Content-Type: application/json
  - body: { model, messages }
  - text = choices[0].message.content, usage = 응답의 usage (prompt_tokens, completion_tokens). 없으면 null.
- 나중에 다른 제공자를 붙일 수 있게, 화면 코드는 callAI만 부르고 OpenRouter 세부 사항은 몰라야 해.
- 오류 처리: 네트워크 오류, HTTP 오류(상태 코드와 응답 메시지 일부 표시), 빈 응답 → 토스트로 알리고 그림은 그대로 둠.
- 호출 중에는 찍기 버튼을 "찍는 중…"으로 바꾸고 비활성화. [취소] 버튼으로 AbortController 중단 가능.

## 3. 대상 칸과 같이 보낼 그림 (프로그램이 결정, AI가 고르지 않음)
- 대상: 지금 선택된 칸(cur) 하나뿐. AI 결과는 이 칸에만 적용.
- 생성 / 수정 자동 판단:
  - 대상 칸이 비어 있으면 "생성", 그림이 있으면 "수정" (대상 칸 그림을 같이 보냄).
  - "현재 그림 무시하고 새로 그리기" 체크박스를 켜면 그림이 있어도 "생성"으로 처리하고 대상 그림은 보내지 않음.
- 참고 프레임 자동 선택 (비어 있는 칸은 항상 제외, 대상 칸 자신도 제외):
  | 대상 칸 | 참고로 같이 보낼 프레임 |
  |---|---|
  | MZ 아래 정지 (아래 패턴 1) | 없음 |
  | MZ 왼쪽·오른쪽·위의 정지 (패턴 1) | 아래 정지 + (있으면) 왼쪽 정지 |
  | MZ 걷기 패턴 0 또는 2 | 같은 방향의 정지 (패턴 1) |
  | 자유 모드 | 바로 앞 프레임 (cur > 0 이고 비어 있지 않을 때만) |
  - 한 번에 보내는 그림은 대상 포함 최대 3장.
- AI 패널에 지금 보낼 내용을 한 줄로 표시하고, 칸 선택이 바뀔 때마다 갱신:
  예) "대상: 오른쪽 1(정지) · 수정 · 참고: 아래 정지, 왼쪽 정지"

## 4. 그림 텍스트 형식 (보낼 때와 받을 때 같은 형식)
- 기호: 0-9, a-z (소문자 36개). 0은 항상 투명. 색은 최대 35개.
- 형식:
  ```
  PALETTE
  0 transparent
  1 #rrggbb
  2 #rrggbb
  ...
  GRID
  (N줄, 각 줄은 정확히 N글자)
  END
  ```
- 보낼 때만: AI가 좌표를 셀 수 있게 줄 번호와 열 눈금을 붙임.
  ```
      0         1         2         3         4
      012345678901234567890123456789012345678901234567
  00| 000000000000000001111100000000000000000000000000
  01| 000000000000000013333310000000000000000000000000
  ```
  - 같이 보내는 모든 그림(대상 + 참고)은 팔레트 하나를 공유.
  - 보낼 그림의 색이 35개를 넘으면, 많이 쓰인 35색만 남기고 나머지는 가장 가까운 색으로 바꿔서 보냄
    (보내는 텍스트에서만. 실제 그림은 바꾸지 않음). 이때 디버그 영역에 "색 N개를 줄여서 보냄" 표시.
- 받을 때: 줄 번호·눈금 없이 위 형식 그대로만 받음 (5. 응답 파싱 참고).

## 5. AI에게 보내는 프롬프트
- system 메시지:
  - 4번 출력 형식을 엄격하게 지정. 설명, 코드 블록, 다른 글자 없이 이 형식만 출력하라고 명시.
  - 입력 그림의 줄 번호(00|)와 눈금은 좌표 참고용이며 출력에는 넣지 말라고 명시.
  - 좌표는 x = 열(왼쪽 0), y = 줄(위쪽 0).
- user 메시지에 자동으로 포함:
  - 사용자가 쓴 프롬프트
  - 캔버스 크기 N (MZ 모드면 48)
  - 생성인지 수정인지. 수정이면 "아래 대상 그림을 요청대로 고친 결과 전체를 출력. 요청과 관계없는 픽셀은 그대로 유지"
  - MZ 모드면: RPG Maker MZ 걷기 캐릭터라는 것, 대상 방향(아래/왼쪽/오른쪽/위), 대상 패턴
    (패턴 1 = 정지 자세, 0·2 = 걷는 중 발 위치). 발이 프레임 아래쪽에 닿게, 몸은 가로 가운데에.
  - 참고 프레임이 있으면 각각 "참고: 아래 정지" 같은 이름을 붙여서. "같은 캐릭터이니 색·비율·옷을 맞출 것"
  - 대상 그림 (수정일 때만)
  - 자유 모드면: N×N 도트 그림이라는 것만.

## 6. 화면
- 편집 영역(팔레트 아래 또는 미리보기 패널 근처)에 "AI로 찍기" 패널 추가:
  - 3번의 "대상 · 생성/수정 · 참고" 한 줄 표시
  - 프롬프트 입력칸 (textarea, 예: "갈색 머리 소년, 파란 옷, 갈색 신발" / "머리를 한 칸 위로")
  - "현재 그림 무시하고 새로 그리기" 체크박스
  - [찍기] 버튼, 호출 중엔 [취소] 버튼
  - [응답 직접 붙여넣기] 버튼: 다른 곳에서 받은 AI 응답 텍스트를 붙여넣어 같은 파서로 대상 칸에 적용.
    (API 비용 없이 파서를 테스트하고, 채팅 화면에서 받은 결과도 쓸 수 있게)
  - [보낼 프롬프트 복사] 버튼: 지금 보낼 system+user 메시지 전체를 클립보드로 복사
    (채팅 화면에 붙여넣어 쓰거나, 보내는 내용 확인용)
  - 접을 수 있는 <details> "디버그":
    - 마지막으로 보낸 메시지 전체
    - 마지막 응답 원문 + 파싱 실패 시 실패 이유
    - 보낸 글자 수, 토큰 사용량(usage가 있으면 입력/출력 토큰, 없으면 "알 수 없음")
- 모바일(360px)·다크모드에서 깨지지 않게.

## 7. 응답 파싱
- 관대하게 받을 것: 앞뒤 공백, ``` 코드 블록 감싸기, 팔레트 hex 대소문자, 격자 글자 대소문자(소문자로 변환), 줄 끝 공백,
  AI가 실수로 붙인 줄 번호 접두어("00| " 형태)는 떼고 처리.
- 엄격하게 거부할 것 (하나라도 걸리면 적용하지 않고 실패 이유를 토스트 + 디버그 영역에 표시):
  - PALETTE / GRID 구간을 못 찾음
  - 팔레트 색이 #rrggbb 형식이 아님, 0이 투명이 아님, 기호가 0-9a-z가 아님
  - GRID 줄 수가 N이 아님 (몇 줄이었는지 표시)
  - 어떤 줄의 글자 수가 N이 아님 (몇 번째 줄이 몇 글자였는지 표시)
  - PALETTE에 정의되지 않은 기호 사용
- 변환: 0 → '' (투명), 나머지 → '#rrggbb' 소문자. 기존 frames 저장 형식과 똑같이.

## 8. 적용
- 파싱 성공 시: pushUndo() → frames[cur]에 적용 → 썸네일·편집 캔버스·저장 갱신 (기존 commit 흐름 사용).
- 호출 중에 사용자가 다른 칸을 선택했더라도, 결과는 호출을 시작할 때의 대상 칸에 적용.
- AI 팔레트 색(투명 제외)을 "이 그림의 색" 줄(importColors, 최대 32)에 표시.
- 대상 칸 외의 다른 프레임은 절대 건드리지 않음.

## 9. 완료 확인 기준 (이걸 다 만족해야 함)
1. [응답 직접 붙여넣기]로 올바른 48×48 응답을 넣으면 대상 칸에 정확히 적용되고, 되돌리기 한 번으로 적용 전으로 돌아감.
   다른 11칸은 픽셀 단위로 변하지 않음.
2. 줄 수가 틀린 응답, 글자 수가 틀린 줄이 있는 응답, 정의 안 된 기호를 쓴 응답, 코드 블록으로 감싼 올바른 응답,
   줄 번호("00| ")가 붙은 올바른 응답을 각각 넣었을 때: 앞의 셋은 거부되고 그림이 그대로이며, 뒤의 둘은 정상 적용됨.
3. [보낼 프롬프트 복사]로 확인했을 때 참고 프레임이 3번 표대로 선택됨:
   - 빈 칸은 참고에서 빠짐
   - 대상 칸이 비어 있으면 "생성"이고 대상 그림이 없음
   - "새로 그리기" 체크 시 대상 그림이 없음
   - 보내는 격자에 줄 번호와 열 눈금이 있음
4. 프로젝트 JSON으로 저장한 파일 안에 API 키가 없음.
5. 키/모델이 비었을 때, 네트워크 오류일 때, HTTP 오류일 때 그림이 바뀌지 않고 알림이 뜸.
6. 모델 이름만 바꾸면 다른 모델로 호출됨 (코드 수정 없이). 응답 후 디버그에 토큰 사용량이 표시됨.
7. 자유 모드(16×16 등)에서도 N에 맞춰 동작함.
8. 기존 기능(그리기, MZ 내보내기/불러오기, GIF, JSON 저장/불러오기)이 이전과 똑같이 동작.
9. 다크모드/모바일 화면에서 AI 패널이 깨지지 않음.
