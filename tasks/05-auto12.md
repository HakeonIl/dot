AI 찍기에 "참고 이미지 첨부"와 "MZ 12장 자동 찍기"를 추가해 줘. 이번 작업 목표는 이 두 가지야.
명령(이동·색 교체) 방식 수정, Batch API, 병렬 생성은 아직 넣지 마.

배경: 지금은 MZ 캐릭터 12칸을 한 칸씩 골라서 프롬프트를 바꿔 가며 9번 찍고, 오른쪽은 [왼쪽→오른쪽 반전복사]로 채우고 있어.
이걸 (1) 캐릭터 그림을 첨부해서 "이 캐릭터를 도트로" 찍을 수 있게 하고,
(2) 캐릭터 설명이나 그림만 주면 12칸을 정해진 순서대로 한 번에 끝까지 찍게 하려는 거야.
양이 많으니 맨 아래 "작업 순서"대로 하나씩 끝내면서 진행해.

## 1. 먼저 할 리팩터 (동작 변경 없음)
자동 찍기는 "지금 선택한 칸(cur)"과 "#aiPrompt 입력칸"이 아닌 다른 칸·다른 문장으로 메시지를 만들어야 해.
- aiContext(target, opts): target을 받게. 생략하면 지금처럼 cur.
  opts.forceCreate(true면 생성), opts.noRefs(true면 참고 그림 없음)를 받을 수 있게. 생략하면 지금과 같음
  (forceCreate 생략 시 #aiForceNew 체크 상태 사용).
- aiBuildMessages(snap, ctx, n, opts): opts.prompt가 있으면 #aiPrompt 대신 그 문장, opts.image가 있으면 3번처럼 첨부.
- applyAiFrameTo(target, frame, colors, opts): opts.noUndo가 true면 pushUndo를 하지 않음.
- 이 단계가 끝나면 기존 찍기·후보·붙여넣기 결과가 이전과 똑같은지 가짜 모델로 확인.

## 2. 참고 이미지 첨부 (UI)
- AI 패널의 프롬프트 칸 아래에 "참고 이미지" 줄: [이미지 선택] 버튼(숨긴 input type=file, accept="image/png,image/jpeg,image/webp,image/gif"),
  작은 미리보기(최대 64px, image-rendering: pixelated 아님. 원본 그림이니 부드럽게), 파일 이름과 크기, [지우기].
- 고른 이미지는 canvas로 줄여서 저장:
  긴 변이 512px보다 크면 512px로 비율 유지 축소, 작으면 그대로. PNG data URL로 변환(투명 유지).
  변환된 data URL이 1.5MB를 넘으면 JPEG 0.9로 다시 변환(흰 배경). 그래도 넘으면 "이미지가 너무 커요" 안내 후 첨부 안 함.
- 첨부한 이미지는 메모리와 localStorage 'dot-gongbang.aiimg'에 {name, w, h, dataUrl} 형태로 저장 (저장 실패해도 조용히 메모리만).
  새로고침 후에도 남아 있어야 함. 프로젝트 JSON 저장/불러오기, MZ 내보내기에는 들어가지 않음.
- 모델 정보(aiLoadModels)에 architecture.input_modalities도 같이 보관.
  지금 모델이 목록에 있고 input_modalities에 "image"가 없으면, 이미지가 첨부된 동안 이미지 줄 아래에
  "이 모델은 이미지를 받을 수 없어요" 경고. 이 상태에서 [찍기]·[12장 자동 찍기]는 막고 같은 안내를 토스트로.
  모델 정보를 못 불러왔거나 목록에 없는 모델, test/ 모델이면 막지 않음.

## 3. 참고 이미지 첨부 (요청)
- 이미지가 첨부돼 있고 "이미지를 보낼 단계"일 때만 user 메시지 content를 배열로 보냄:
  [{type: "text", text: <지금 만드는 user 문장 전체>}, {type: "image_url", image_url: {url: <dataUrl>}}]
  system 메시지는 지금처럼 문자열.
- 이미지를 보낼 때 user 문장 맨 앞(사용자 프롬프트 앞)에 아래 문장을 추가:
  "Attached image: the character design to follow. Redraw this character as a {N}x{N} pixel sprite in the required format.
  Match its hair, face, clothes and main colors; simplify small details so they read at this size. Do not copy the image resolution or background."
  ({N}은 캔버스 크기)
- 이미지를 보내는 단계:
  - 자유 모드: 항상.
  - MZ 모드 수동 찍기: 대상이 패턴 1(정지)일 때만. 걷기 칸(패턴 0·2)은 정지 그림을 참고로 받으니 이미지는 안 보냄.
  - 4번 자동 찍기: 4번 단계 표의 "이미지" 칸을 따름.
- 이미지 data URL(base64)은 디버그, 보낸 메시지 전문, [보낼 프롬프트 복사], 기록, 기록 원문, CSV 어디에도 나오면 안 됨.
  대신 "[참고 이미지: cat.png 512x384, 210KB]"처럼 한 줄로 표시.
  - aiBodyText: content가 배열인 경우 text 부분 글자 수만 세고, "(messages 2개, 12345자, 이미지 1개 210KB)"로 요약.
  - 보낸 메시지 전문(sentFull)과 [보낼 프롬프트 복사]: USER 부분 끝에 위 한 줄 표시.
  - 기록 항목에 img 필드 추가 ("cat.png 512x384" 또는 ''). 기록 표·CSV에 "참고 이미지" 칸 추가.
- 가짜 모델(test/): 이미지가 있어도 똑같이 동작. aiFakeUsage는 text 글자 수/4 + 이미지 1장당 1000 토큰으로 계산.
  (지금 aiFakeUsage는 String(content)로 세서 배열이면 "[object Object]"가 됨. 고칠 것)
- 이미지 때문에 요청이 실패하는 경우(400 등)는 기존 오류 안내 그대로. 따로 처리하지 않음.

## 4. MZ 12장 자동 찍기
MZ 모드에서만 AI 패널에 [12장 자동 찍기] 버튼 (자유 모드에서는 숨김).
누르면 설정 대화상자 → [시작] → 진행 대화상자에서 끝까지 순서대로 찍음.

### 4-1. 설정 대화상자
- 캐릭터 설명 textarea: 처음 열 때 #aiPrompt 값으로 채움. 'dot-gongbang.ai'에 따로 저장.
- 참고 이미지: 2번에서 첨부한 것을 그대로 씀. 대화상자 안에 같은 미리보기와 [이미지 선택]/[지우기] (같은 데이터를 공유).
- 설명과 이미지가 둘 다 비어 있으면 [시작] 비활성화.
- 오른쪽 방향: (●) 왼쪽을 반전해서 채우기 (기본) / ( ) AI로 찍기
- 이미 그림이 있는 칸: (●) 건너뛰기 (기본) / ( ) 모두 새로 찍기
- 실패 시 재시도: 단계마다 최대 [2]번 (0~3)
- 아래에 안내 한 줄: "AI 호출 약 9번(오른쪽 AI면 12번) · 모델: <모델> · 형식: <형식>".
  모델 가격을 알면 지난 기록의 같은 모델·형식 평균 비용 × 호출 수로 "예상 비용 약 $0.12"도 표시 (기록이 없으면 생략).
- 출력 형식, 자동 보정, 추론 강도 등은 지금 AI 설정·패널 값을 그대로 씀. 후보 수는 무시하고 단계마다 1장.
- [시작]을 누른 순간 설정을 한 번 복사(aiSnapSettings)해서 끝까지 그 값만 씀.

### 4-2. 단계 (이 순서로 하나씩. 앞 단계 결과가 뒤 단계의 참고 그림이라 병렬로 하면 안 됨)
| # | 대상 칸 | 방식 | 참고 그림 | 이미지 | 자세 문장(아래 4-3) |
|---|---|---|---|---|---|
| 1 | 아래 정지 | 생성 | 없음 | 보냄 | DOWN_STAND |
| 2 | 왼쪽 정지 | 생성 | 아래 정지 | 보냄 | LEFT_STAND |
| 3 | 위 정지 | 생성 | 아래 정지, 왼쪽 정지 | 보냄 | UP_STAND |
| 4 | 오른쪽 정지 (AI일 때만) | 생성 | 아래 정지, 왼쪽 정지 | 보냄 | RIGHT_STAND |
| 5 | 아래 걷기 0 | 수정 | 없음 | 안 보냄 | DOWN_WALK_0 |
| 6 | 아래 걷기 2 | 수정 | 없음 | 안 보냄 | DOWN_WALK_2 |
| 7 | 왼쪽 걷기 0 | 수정 | 없음 | 안 보냄 | LEFT_WALK_0 |
| 8 | 왼쪽 걷기 2 | 수정 | 없음 | 안 보냄 | LEFT_WALK_2 |
| 9 | 위 걷기 0 | 수정 | 없음 | 안 보냄 | UP_WALK_0 |
| 10 | 위 걷기 2 | 수정 | 없음 | 안 보냄 | UP_WALK_2 |
| 11 | 오른쪽 걷기 0 (AI일 때만) | 수정 | 없음 | 안 보냄 | RIGHT_WALK_0 |
| 12 | 오른쪽 걷기 2 (AI일 때만) | 수정 | 없음 | 안 보냄 | RIGHT_WALK_2 |
| 13 | 오른쪽 3칸 (반전일 때만) | 반전 | - | - | 호출 없음 |

- 정지 단계(생성): aiContext(target, {forceCreate: true})의 참고 그림 규칙이 위 표와 같으니 그대로 씀.
- 걷기 단계(수정): 호출 직전에 그 방향 정지 그림을 대상 칸에 복사하고(frames[target] = 정지 그림 복사본),
  aiContext(target, {forceCreate: false, noRefs: true})로 "Target picture"만 보냄.
  (대상 칸이 정지 그림 복사본이라 참고 그림까지 보내면 같은 그림이 두 번 들어감)
  실패하면 그 칸을 복사 전 상태로 되돌림.
- 반전 단계: 오른쪽 패턴 0·1·2 = flipFrameH(왼쪽 패턴 0·1·2, 48). 호출 없음.
- 보내는 user 프롬프트 = 캐릭터 설명 + "\n" + 자세 문장. 설명이 비어 있으면 자세 문장만.
  (방향·패턴·"발은 바닥에" 문장과 생성/수정 문장은 aiBuildMessages가 지금처럼 붙임)
- "건너뛰기" 설정일 때:
  - 정지 칸: 그림이 있으면 건너뜀 (그 그림을 뒤 단계의 참고로 씀).
  - 걷기 칸: 그림이 있고 그 방향 정지 그림과 다르면 건너뜀. 정지 그림과 픽셀이 똑같으면(복사만 해 둔 칸) 찍음.
  - 반전: 오른쪽 칸 중 빈 칸에만 반전 그림을 넣음.
  - 실패로 멈춘 뒤 다시 [12장 자동 찍기]를 누르면 성공한 칸은 건너뛰고 이어서 찍게 되는 게 목적.
- "모두 새로 찍기" 설정일 때: 모든 칸을 위 표대로 다시 찍음 (정지 칸은 생성, 걷기 칸은 정지 그림 복사 후 수정).

### 4-3. 자세 문장 (ai.js에 상수 표 AI_AUTO_POSES로. 나중에 내가 직접 고칠 거라 한곳에 모아 둬)
- DOWN_STAND: "Front view facing the viewer, standing still. Both eyes visible, arms at the sides, feet together, nearly left-right symmetric."
- LEFT_STAND: "Same character as the reference pictures: same colors, height, head size and outline. Side view facing LEFT, standing still. Only one eye visible, face points left. Feet together."
- UP_STAND: "Same character as the reference pictures: same colors, height, head size, body width and outline. Back view, standing still. Face not visible, only the back of the head. Arms at the sides, feet together."
- RIGHT_STAND: "Same character as the reference pictures: same colors, height, head size and outline. Side view facing RIGHT, standing still. It should look like the left-facing reference flipped horizontally. Feet together."
- DOWN_WALK_0: "Walking pose. Change only the legs and arms: the viewer-left foot steps forward (1 pixel lower), the viewer-right foot steps back (looks shorter). Arms swing slightly opposite to the legs. Keep the head, face and torso pixels unchanged."
- DOWN_WALK_2: DOWN_WALK_0에서 viewer-left와 viewer-right를 바꾼 문장.
- LEFT_WALK_0: "Walking pose, side view facing left. Change only the legs and arms: the near leg steps forward (to the left), the far leg steps back (to the right), legs apart. Draw the far leg one shade darker. Arms swing opposite to the legs. Keep the head, face and torso pixels unchanged."
- LEFT_WALK_2: LEFT_WALK_0에서 near와 far를 바꾼 문장 (far leg forward, near leg back. 먼 다리는 여전히 어둡게).
- UP_WALK_0: "Walking pose, back view. Change only the legs and arms: the viewer-left foot steps forward (away from the viewer, looks shorter), the viewer-right foot steps back (sole slightly visible). Arms swing slightly opposite to the legs. Keep the head and torso pixels unchanged."
- UP_WALK_2: UP_WALK_0에서 viewer-left와 viewer-right를 바꾼 문장.
- RIGHT_WALK_0 / RIGHT_WALK_2: LEFT_WALK_0 / 2에서 left↔right를 바꾼 문장.

### 4-4. 진행 대화상자
- showModal()로 열어서 진행 중에는 그림 편집·모드 변경·단축키가 막히게 (main.js의 dialog[open] 검사가 이미 단축키를 막음).
- 단계 목록: 단계마다 작은 썸네일 + "아래 정지 · 생성 · 성공 · 2.1초 · $0.0031" 같은 한 줄.
  상태: 대기 / 진행 중 / 성공 / 성공(재시도 1번) / 건너뜀 / 반전 / 실패 / 중지됨.
- 위쪽에 전체 진행 "3 / 10 단계 · 경과 1분 12초 · 누적 비용 $0.0123 (추정이 섞이면 '(추정 포함)')".
- [중지] 버튼: 진행 중인 호출을 취소하고 남은 단계를 "중지됨"으로. 이미 적용된 칸은 그대로 둠.
- 끝나면 [중지]를 숨기고 [닫기]. 닫으면 현재 칸을 아래 정지로 옮기고, 미리보기는 지금 설정 그대로.
- 360px 폭에서 가로 스크롤 없이, 목록은 대화상자 안에서만 세로 스크롤.

### 4-5. 실패·재시도·되돌리기
- 재시도하는 실패: 형식 오류(parseAiResponse 실패), 빈 응답, 응답 오류(200 안의 error), 네트워크 오류, HTTP 429·5xx.
  429·5xx·네트워크 오류는 2초 기다렸다가 재시도 (기다리는 중에도 [중지]로 취소 가능).
  seed를 정했으면 재시도마다 seed + 재시도 번호.
- 바로 멈추는 실패: HTTP 400·401·402·403·404, finish_reason "length" (재시도해도 똑같으니 기존 AI_LENGTH_MSG 안내).
- 한 단계가 재시도까지 다 실패하면 전체를 멈추고 남은 단계는 "앞 단계 실패로 중단". 앞에서 성공한 칸은 그대로 둠.
  실패 이유는 지금처럼 aiFormatError/aiGuidance 안내 문구로 단계 줄과 토스트에 표시.
- 되돌리기: [시작]할 때 pushUndo() 한 번만 하고, 단계별 적용은 applyAiFrameTo(..., {noUndo: true}).
  끝난 뒤(성공·실패·중지 모두) 되돌리기 한 번이면 시작 전 12칸으로 돌아가야 함.
- 단계마다 적용 직후 save() (중간에 브라우저가 닫혀도 그때까지 찍은 칸은 남게).
- 진행 중에 캔버스 크기나 모드가 바뀔 일은 없지만(모달), 그래도 적용 직전에 isMz()와 N === 48을 확인하고 아니면 중단.

### 4-6. 디버그·기록
- 디버그는 단계마다 지금 찍기와 똑같이 갱신 (마지막 호출 내용이 보이게).
- 모든 호출(재시도 포함)을 aiLogCall로 기록. 기록 항목에 auto 필드 추가: "자동 3/10" (재시도면 "자동 3/10 재시도 1").
  기록 표·CSV에 "자동" 칸 추가. prompt 칸에는 캐릭터 설명 앞부분 대신 자세 키(DOWN_STAND 등)를 넣음.
- 건너뜀·반전 단계는 호출이 없으니 기록하지 않음.

### 4-7. 가짜 모델로 확인할 수 있게
- 자동 찍기에서 가짜 응답은 "실행 중 호출 순번(재시도 포함, 0부터)"번째 응답을 씀 (fakeIndex로 전달).
  예) 가짜 응답 10개를 =====로 나눠 넣고 3번째를 틀린 형식으로 두면, 3번째 호출이 실패하고 4번째 응답으로 재시도.

## 5. 완료 확인 기준
(가짜 모델 test/…로 비용 없이 확인. 가짜 응답은 48x48 줄번호 격자로 만들어 쓰면 됨)
1. 이미지를 첨부하지 않은 기존 찍기·후보·붙여넣기의 "보낸 요청 body"가 이번 작업 전과 같음.
2. 이미지 첨부 후 자유 모드 찍기: 디버그 body 요약에 "이미지 1개 …KB", 보낸 메시지 전문에 "[참고 이미지: …]" 한 줄.
   디버그·[보낼 프롬프트 복사]·기록·기록 원문·CSV 어디에도 "data:image"나 base64가 없음.
3. 2000x1000 이미지를 고르면 512x256으로 줄어서 표시되고, 새로고침 후에도 첨부가 남아 있음.
   프로젝트 JSON에는 이미지가 없음.
4. MZ 모드 수동 찍기: 정지 칸에서는 이미지가 가고, 걷기 칸에서는 안 감.
5. 모델 목록에서 input_modalities에 image가 없는 모델 이름을 넣고 이미지를 첨부하면 경고가 뜨고 찍기가 막힘.
   이미지를 지우면 다시 찍을 수 있음. test/ 모델은 막지 않음.
6. MZ 빈 12칸 + 오른쪽 반전 + 가짜 응답 9개 → 진행 대화상자에 단계가 차례대로 성공하고 12칸이 모두 채워짐.
   오른쪽 3칸은 왼쪽 3칸의 좌우 반전과 픽셀 단위로 같음. 기록에 "자동 n/10"으로 9줄 추가.
7. 걷기 단계의 보낸 메시지에 "Reference:" 블록이 없고 "Target picture:"만 있으며, 그 그림이 그 방향 정지 그림과 같음.
   위 정지 단계의 메시지에는 아래 정지·왼쪽 정지 두 참고 그림이 있음.
8. 3번째 가짜 응답을 틀린 형식으로 두면 3단계가 "성공(재시도 1번)"이 되고 기록에 재시도 줄이 남음.
   재시도 0번으로 두면 3단계 실패, 4단계부터 "앞 단계 실패로 중단", 1·2단계 칸은 남아 있음.
9. 8번에서 멈춘 상태로 다시 자동 찍기(건너뛰기) → 1·2단계는 "건너뜀", 3단계부터 이어서 찍음.
10. 진행 중 [중지] → 진행 중인 호출이 취소되고 남은 단계 "중지됨", 기록에 "취소".
11. 자동 찍기가 끝난 뒤(성공·실패·중지 각각) 되돌리기 한 번이면 시작 전 12칸과 픽셀 단위로 같음.
12. "!http 401 {…}" 가짜 응답 → 재시도하지 않고 바로 멈추며 기존과 같은 한국어 안내.
    "!empty length" → 재시도 없이 AI_LENGTH_MSG 안내로 멈춤.
13. 오른쪽 "AI로 찍기"를 고르면 12번 호출, 단계 4·11·12가 RIGHT_* 문장으로 나감.
14. 자유 모드에서는 [12장 자동 찍기] 버튼이 안 보임.
15. 다크모드·360px에서 새 UI(이미지 줄, 설정 대화상자, 진행 대화상자)가 깨지지 않고 페이지 가로 스크롤 없음.
    file://로 열었을 때 콘솔 오류 0개.
16. 실제 OpenRouter 이미지 지원 모델 하나로 자동 찍기를 끝까지 한 번 돌려 봄 (가능하면. 비용이 드니 못 했으면 못 했다고).
